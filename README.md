# Cybersecurity Incident Severity Prediction System

A machine learning project for **MLOps-I** that predicts the triage verdict (`IncidentGrade`) of security incidents using the **Microsoft GUIDE dataset**. The trained machine learning models are served through a lightweight **Flask REST API** (`api.py`) and visualized using an interactive **Streamlit dashboard** (`app.py`).

---

## 1. Project Introduction
In modern Security Operations Centers (SOCs), analysts face an overwhelming volume of security alerts every day. Investigating each alert manually causes alert fatigue and delays responses to real attacks. 

This project implements an end-to-end Machine Learning pipeline that classifies cybersecurity incidents into their triage grades, allowing security teams to quickly prioritize genuine threats.

---

## 2. Problem Statement
Many security alerts generated by automated detection systems turn out to be false positives or benign activities. Security analysts need an automated decision-support system to classify incoming incident reports accurately and efficiently.

**Target Column:** `IncidentGrade`
The dataset categorizes incidents into three classes:
- **`TruePositive`**: Confirmed security threat requiring immediate action (High severity).
- **`BenignPositive`**: Legitimate, expected user or administrative activity (Medium severity).
- **`FalsePositive`**: Incorrect alert with no security threat (Low severity).

---

## 3. Project Objectives
- Train and compare two fundamental machine learning algorithms: **Logistic Regression** and **Random Forest Classifier**.
- Follow standard data preprocessing: missing value imputation, categorical encoding, and feature scaling using Scikit-learn pipelines.
- Build a beginner-friendly **Flask REST API** (`api.py`) to serve real-time predictions.
- Connect a modern **Streamlit frontend** (`app.py`) to the Flask backend via HTTP requests.
- Provide model comparison tables, confusion matrices, and live prediction testing.

---

## 4. Dataset Description
- **Dataset Name:** Microsoft Security Incident Prediction (GUIDE) Dataset.
- **Source Files:**
  - `dataset/GUIDE_Train.csv` (Training incidents, ~2.4 GB)
  - `dataset/GUIDE_Test.csv` (Test incidents, ~1.08 GB)
  - `dataset/GUIDE_Test_Queue_Rankings.csv`
- **Sampling:** To allow fast local training without modifying the original dataset, a stratified/random sample of 50,000 labelled rows is used.
- **Features Used:** 24 features (3 numeric time features: `Hour`, `DayOfWeek`, `Month`; and 21 categorical/code features such as `OrgId`, `DetectorId`, `AlertTitle`, `Category`, `MitreTechniques`, etc.).
- **Data Splitting:** Data is split 80% train / 20% test using `GroupShuffleSplit` on `IncidentId` to ensure no alert from the same incident appears in both train and test sets (0 data leakage).

## 6. Machine Learning Algorithms
1. **Logistic Regression (Baseline Model):**
   - Linear classification model using regularized cross-entropy loss.
   - Fast to train and provides an interpretable baseline.
   - Configured with `class_weight="balanced"` to handle class imbalance.
2. **Random Forest Classifier (Primary Model):**
   - Ensemble of 100 decision trees.
   - Captures non-linear relationships and interactions among categorical and numeric incident attributes.
   - Configured with `min_samples_leaf=3`, `class_weight="balanced"`, and parallel processing (`n_jobs=-1`).

---

## 7. Training and Testing Process
1. **Data Ingestion:** Load 50,000 sample rows from `dataset/GUIDE_Train.csv`.
2. **Feature Engineering:** Extract `Hour`, `DayOfWeek`, and `Month` from `Timestamp`. Drop direct identifier columns (e.g. raw IP, file paths, hashes) to prevent memorization.
3. **Preprocessing Pipeline (`ColumnTransformer`):**
   - **Numeric features:** `SimpleImputer(strategy="median")` + `StandardScaler()`.
   - **Categorical features:** `SimpleImputer(strategy="most_frequent")` + `OneHotEncoder(handle_unknown="infrequent_if_exist")`.
4. **Group Split:** 80/20 train/test split grouped by `IncidentId` (Train rows: 40,150 | Test rows: 9,850).
5. **Model Evaluation:** Measure Accuracy, Precision, Recall, Weighted F1, Macro F1, and generate confusion matrices.
6. **Artifact Saving:** Models and preprocessor pipelines saved to `models/` directory; graphs and metrics saved to `outputs/`.

## 9. Backend API (`api.py`)
The backend is implemented using **Flask** and exposes REST endpoints on `http://127.0.0.1:8000`:

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` or `/health` | Health check endpoint returning service status and model state |
| `GET` | `/metrics` | Returns model evaluation comparison table as JSON |
| `GET` | `/logs` | Returns in-memory request logs (newest first) |
| `POST` | `/predict` | Receives incident data JSON and returns model prediction and probabilities |

### Example Request Body for `/predict`:
```json
{
  "record": {
    "OrgId": "1234",
    "DetectorId": "5678",
    "AlertTitle": "Suspicious Activity",
    "Category": "InitialAccess",
    "MitreTechniques": "T1078",
    "EntityType": "User",
    "SuspicionLevel": "Medium",
    "Timestamp": "2024-06-04T12:00:00.000Z"
  }
}
```

### Example Response:
```json
{
  "success": true,
  "prediction": "FalsePositive",
  "probabilities": {
    "BenignPositive": 0.4082,
    "FalsePositive": 0.4306,
    "TruePositive": 0.1612
  },
  "message": "Prediction completed successfully"
}
```

## 13. Commands to Run the Project

